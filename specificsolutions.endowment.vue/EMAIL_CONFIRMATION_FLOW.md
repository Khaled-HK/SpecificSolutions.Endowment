# تدفق تأكيد البريد الإلكتروني - Email Confirmation Flow

## نظرة عامة

تم تحسين نظام تأكيد البريد الإلكتروني لمعالجة حالة عدم تأكيد البريد الإلكتروني عند تسجيل الدخول بشكل أفضل.

## الصفحات المضافة/المحدثة

### 1. صفحة عدم تأكيد البريد الإلكتروني الجديدة
**الملف:** `src/pages/email-not-confirmed.vue`

**الوظيفة:**
- صفحة مخصصة لمعالجة حالة عدم تأكيد البريد الإلكتروني
- تعرض رسالة واضحة للمستخدم
- توفر روابط مباشرة لصفحات التأكيد وإعادة الإرسال
- تحتوي على تعليمات مفصلة ونصائح مفيدة

**الميزات:**
- تصميم متجاوب ومتسق مع باقي النظام
- رسائل واضحة باللغة العربية
- روابط مباشرة لجميع الإجراءات المطلوبة
- نصائح مفيدة للمستخدم

### 2. تحديث صفحة تسجيل الدخول
**الملف:** `src/pages/login.vue`

**التحسينات:**
- إزالة التنبيهات المعقدة
- تبسيط واجهة المستخدم
- الاعتماد على التوجيه التلقائي للصفحة المخصصة

### 3. تحديث useLogin Composable
**الملف:** `src/composables/useLogin.ts`

**التحسينات:**
- تحسين كشف حالة عدم تأكيد البريد الإلكتروني
- التوجيه التلقائي للصفحة المخصصة
- معالجة أفضل للأخطاء

## تدفق العمل الجديد

### عند تسجيل الدخول:

1. **المستخدم يدخل بيانات تسجيل الدخول**
2. **النظام يرسل طلب تسجيل الدخول للباك إند**
3. **الباك إند يرد بإحدى الحالات:**

   **أ) نجح تسجيل الدخول:**
   - يتم تسجيل الدخول وتوجيه المستخدم للوحة التحكم
   
   **ب) فشل تسجيل الدخول - عدم تأكيد البريد الإلكتروني:**
   - النظام يكشف رسالة الخطأ
   - يتم توجيه المستخدم تلقائياً لصفحة `email-not-confirmed`
   - يتم تمرير البريد الإلكتروني كمعامل في الرابط

### في صفحة عدم تأكيد البريد الإلكتروني:

1. **المستخدم يرى رسالة واضحة**
2. **يمكنه اختيار أحد الخيارات:**
   - الذهاب لصفحة تأكيد البريد الإلكتروني
   - إعادة إرسال بريد التأكيد
   - العودة لصفحة تسجيل الدخول

## كشف حالة عدم التأكيد

النظام يكشف حالة عدم تأكيد البريد الإلكتروني من خلال **حقل محدد من الباك إند** (نمط خالد):

```typescript
// الاعتماد على حقل من الباك إند بدلاً من تحليل النص
if (res.requiresEmailConfirmation === true || 
    res.emailNotConfirmed === true || 
    res.data?.requiresEmailConfirmation === true) {
  
  // توجيه المستخدم للصفحة المخصصة
  router.push(`/email-not-confirmed?email=${encodeURIComponent(credentials.email)}`)
  return
}
```

### التوقعات من الباك إند

الباك إند يجب أن يعيد أحد هذه الحقول:

```json
{
  "isSuccess": false,
  "requiresEmailConfirmation": true,  // ← الحقل الأساسي
  "emailNotConfirmed": true,          // ← بديل
  "data": {
    "requiresEmailConfirmation": true  // ← بديل آخر
  }
}
```

## الصفحات المرتبطة

### 1. صفحة تأكيد البريد الإلكتروني
- **الرابط:** `/confirm-email`
- **الوظيفة:** تأكيد البريد الإلكتروني باستخدام الرمز

### 2. صفحة إعادة إرسال التأكيد
- **الرابط:** `/resend-email-confirmation`
- **الوظيفة:** إعادة إرسال بريد التأكيد

### 3. صفحة عدم التأكيد (جديدة)
- **الرابط:** `/email-not-confirmed`
- **الوظيفة:** معالجة حالة عدم التأكيد

## المزايا

1. **تجربة مستخدم محسنة:**
   - رسائل واضحة ومفهومة
   - توجيه سلس بين الصفحات
   - واجهة متسقة

2. **معالجة شاملة:**
   - تغطية جميع حالات عدم التأكيد
   - روابط مباشرة لجميع الإجراءات
   - تعليمات مفصلة

3. **قابلية الصيانة:**
   - كود منظم ومفصل
   - فصل المسؤوليات
   - سهولة التحديث

4. **التوافق مع نمط خالد:**
   - الاعتماد على الباك إند في تحديد الحالة
   - معالجة الاستجابات فقط
   - عدم إضافة منطق أعمال في الفرونت إند
   - **عدم تحليل النص في الفرونت إند**
   - **الاعتماد على حقول محددة من الباك إند**
